# 工作流总设计（总览索引）

> 权威细则见 [`工作流规格说明.md`](工作流规格说明.md)（v1，实现的唯一输入）；上游定调见 [`../小红书成稿工作流定调结论.md`](../小红书成稿工作流定调结论.md)（已批准）。本文件只做「索引 + 一图流」，不重复细则。

## 一句话

这不是一个「自动发帖机」，而是一套通用创作引擎 + 可换账号档案组成的「分层轻编辑部工作流」：输入一个主题，产出一篇符合小红书平台约束与算法判据的图文笔记，经两次人工确认后发布归档。

## 主流程（九节点一图流）

```
① 档案加载 → ② 对标研究[research.md] → ③ 选题定角[角度陈述]
  → ④ 分镜规划[storyboard.md] → ⑤ 封面生产[cover.png]
  → ★1 视觉母版确认（用户批准封面 + 分镜风格）
  → ⑥ 内页生产[page-NN.png] → ⑦ 文案定稿[copy.md]
  → ⑧ 组包终审[终审报告]
  → ★2 发布放行（用户选定标题 + 明确说「发」）
  → ⑨ 发布与归档[receipt.md + 已发档案.jsonl]
```

节点输入输出、通过标准、失败处理的完整定义见规格 §3 表格；产物字段定义见 [`术语与产物约定.md`](术语与产物约定.md)。

## 自动化边界

- **双确认**：★1 视觉母版确认、★2 发布放行，两点缺一不可，均需用户明确表态，不可由 Agent 代为批准。
- **不自动互动**：任何评论/点赞/回复类 MCP 工具本版一律不调用；评论区首条引导语由用户发布后手动发出（见规格 §6.5）。
- **产物先落盘再发布**：每个节点的产物必须先写入 `06-产出/<run>/`，发布（节点⑨）是流程终点而非产物来源；任何失败不损失已有产物。
- **降级不中断**：对标研究、封面生图等环节失败时走既定降级路径（跳过并记录 / HTML→PNG 兜底），流程继续而不是整体停摆；降级均记入 run.yaml 的 `degradations`。
