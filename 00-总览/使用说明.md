# 小红书工作流 · 使用说明

> 面向第一次接触项目的贡献者和使用者。本文件只提供操作入口；项目定位、公开产出范围、安装与命令契约以 [`../README.md`](../README.md) 为准，流程与状态语义以 [`工作流规格说明.md`](工作流规格说明.md) 为准，主控编排见 [`../03-skills/SKILL.md`](../03-skills/SKILL.md)。

## 开始之前

1. 按 [`README.md` 的“最小运行”](../README.md#最小运行)在仓库根目录依次运行 `npm ci`、`npm test`、`npm run check:config`、`npm run smoke`；各命令的检查范围和失败处理也以该节为准。
2. 把 [`../01-账号/账号档案.example.md`](../01-账号/账号档案.example.md) 复制为被 Git 忽略的 `01-账号/账号档案.md`，再填写本地真实信息。
3. 不要把真实账号档案、Cookie、认证状态、真实运行产物、可执行文件或 `node_modules/` 放入提交；公开示例必须保持虚构或确定性。
4. 研究后端和额外视觉 skill 都是可选能力，安装与许可边界见 [`../README.md`](../README.md#可选能力边界)。

公开 Git 树中的 `06-产出/` 只保留 `00000000-selftest` 与 `00000000-verify-fixture`；本文后续出现的 `<run>` 均指被 Git 忽略的本地真实运行目录，不代表可提交的公开样例。

## 怎么触发

- 新笔记：`/xhs <主题>`，或对 Agent 说「按小红书工作流创作 <主题>」
- 续跑：`继续 <run目录名>`
- 首次建议逐节点协作，这样更容易在 ★1 / ★2 处拍板

## 主流程

```text
① 档案加载 → ② 只读研究 → ③ Topic Gate → ④ 选题定角 → ⑤ 分镜规划
→ ⑥ Style Router → ⑦ 封面生产 → ★1 视觉母版确认 → ⑧ 内页生产
→ ⑨ Visual Gate → ⑩ 文案定稿 → ⑪ 组包终审 → ★2 发布包确认
→ ⑫ Publish Pack
```

Topic Gate 位于研究之后：证据不足或角度重复时先修题，不进入昂贵的视觉生产。Visual Gate 位于全套成图之后：逐页检查尺寸、可读性、一致性、中文正确性和视觉质量，不过的页面重做或降级。字段定义见[`术语与产物约定.md`](术语与产物约定.md)。

## 你需要手动做的事

1. ★1 确认封面、分镜和母版方向
2. ★2 确认标题与图片顺序
3. 手动发布到小红书
4. 发布后把笔记链接发回，让工作流补录 `receipt.md`
5. 发布后 1 小时内手动贴评论区首条引导语

## 研究与视觉是怎么跑的

- 研究：OpenCLI 首选；redbook 在已安装且入口检查通过时可选增强；OpenCLI 不可用时由 xiaohongshu-mcp 兜底
- 封面：`cover-anchor-system` 首选，失败时按路由降级
- 内页：`xhs-visual-director` 首选；清单 / 对比 / 数据 / 密集中文页优先 `guizang-social-card-skill`
- 终极兜底：HTML 模板 + `render.mjs`

## 手动发布包里有什么

`manual-publish.md` 会包含：

- 推荐标题 + 备用标题
- 正文
- 标签
- 评论区首条引导语
- 推荐发布时间
- 发布前人工核对项
- 图片顺序清单

## 真发前置

- 若只做研究与成稿，不需要发布登录态
- 若 OpenCLI 不可用，研究兜底需要 xiaohongshu-mcp 登录态；redbook 是可选增强，不改变该兜底语义
- 不再通过工作流自动发布

## 失败后怎么继续

- 缺账号档案：按 example 创建本地文件，补齐必填字段后重新触发。
- 研究后端都不可用：研究节点标记 `degraded` 并说明“未对标”，不伪造证据；可稍后恢复后端再从研究节点继续。
- Topic Gate 为 `revise`：补充研究或换角度，最多两轮；为 `reject` 时停止当前题目。
- 图片缺失、比例不符或视觉复核不通过：按页面重做或走 fallback；需要人工生图时进入 `waiting_backfill`。
- 等待 ★1 / ★2：状态保持 `waiting_confirm`，回复确认或修改意见后续跑。
- 终审失败：根据 `verify.mjs` 输出回到对应节点修复；不要跳过硬校验。

续跑命令是 `继续 <run目录名>`。`in_progress` 节点的半成品不视为可信，会整节点重跑；已经 `ok`、`degraded` 或已确认的步骤不会无故重复。

## 安全边界

仓库只生成手动发布包，不调用 `publish_content`，不自动评论、点赞、收藏或互动。发布、评论区引导语和发布后链接补录都由用户明确、人工完成。工具允许/禁止清单见 [`../04-工具/工具映射.md`](../04-工具/工具映射.md)。
