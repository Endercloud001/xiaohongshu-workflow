# 术语与产物约定

> 权威来源：[`工作流规格说明.md`](工作流规格说明.md)。本文件是术语表 + 产物 schema 的展开抄录，供实现与断点续跑时快速查阅。

## 一、术语表

| 术语 | 含义 |
|---|---|
| 笔记包 | 一次运行的全部产物：图 + 文案 + 运行记录，落盘于 `06-产出/<run>/` |
| Topic Gate | 研究之后的选题准入审查，输出 `go / revise / reject` |
| Style Router | 封面 / 内页技能路由层，支持手动、半自动、自动三种模式 |
| Visual Gate | 成图后的系统性复核，含确定性校验与逐张读图复核 |
| Publish Pack | 手动发布包，包含标题、正文、标签、评论引导、图片顺序与人工检查项 |
| 回填协议 | 工作流出提示词 → 人工生图放回指定路径 → 工作流校验后继续 |
| 探索模式 | 账号档案的初始状态：前 9-12 篇在 2-3 个候选领域轮换试题 |
| 账号档案 | 可换的账号配置：定位 / 人设 / 受众 / 候选风格 / 领域 |

## 二、产物 Schema

### 2.1 运行目录

```text
06-产出/<YYYYMMDD-slug>/
├── run.yaml
├── research.md
├── research-evidence.json
├── topic-gate.md
├── topic-score.json
├── storyboard.md
├── visual-gate.md
├── visual-review.json
├── manual-publish.md
├── receipt.md
├── prompts/
├── html/
├── assets/
└── images/
```

说明：
- `manual-publish.md` 是人工发布包；`receipt.md` 只在用户手动发布后补录时存在。
- `research-evidence.json`、`topic-score.json`、`visual-review.json` 是新增机器可读产物。

### 2.2 run.yaml

```yaml
run: 20260715-sleep-tips
topic: "用户输入的原始主题或提示词"
profile_version: 1
mode: 探索 | 深耕
domain: "本篇候选领域"
workflow_mode: slim_manual_publish
research_backend: opencli | redbook | xiaohongshu-mcp | none
nodes:
  - id: research
    status: ok | degraded | failed | in_progress | waiting_backfill | waiting_confirm
    tool: "agent-reach(OpenCLI->redbook->xiaohongshu-mcp)"
    retries: 0
topic_gate:
  status: go | revise | reject
  total: 10
  rounds: 1
visual_router:
  mode: auto | semi | manual
  cover_skill: cover-anchor-system
  inner_skill: xhs-visual-director
  fallback_skill: guizang-social-card-skill
visual_gate:
  status: pass | revise | fallback
  fallback_pages: []
publish:
  mode: manual_only
  status: package_ready | manually_published | archived_only
  note_url: null
confirmations: []
degradations: []
```

字段说明：
- `workflow_mode`：缺省时视为旧版 run，按旧版语义续跑。
- `research_backend`：记录本次研究实际命中的后端。
- `topic_gate` / `visual_router` / `visual_gate` / `publish`：是 v2 新增结构化字段。
- `publish.status=package_ready` 表示发布包已就绪，待用户手动发布后补录。

**status 状态枚举（六态，完整）**

| 状态 | 含义 |
|---|---|
| `ok` | 节点正常完成，产物可信 |
| `degraded` | 节点以降级路径完成 |
| `failed` | 节点失败且未恢复 |
| `in_progress` | 节点执行中；中断后整节点重跑 |
| `waiting_backfill` | 等待用户按回填协议放回图片 |
| `waiting_confirm` | 等待用户在确认点做决定 |

## 三、断点续跑规则

- 每个节点开始时将 run.yaml 对应节点置 `status: in_progress`，完成后置 `ok / degraded`，等待人工时置 `waiting_backfill` 或 `waiting_confirm`。
- 接到「继续 <run>」时，从最后一个 `status: ok/degraded` 节点之后继续。
- `waiting_*` 节点从等待动作本身继续。
- 已批准的确认点不重复确认。
- `in_progress` 状态的节点视为产物不可信，整节点重跑。
