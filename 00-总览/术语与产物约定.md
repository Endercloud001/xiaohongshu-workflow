# 术语与产物约定

> 权威来源：[`工作流规格说明.md`](工作流规格说明.md) §1、§3（断点续跑规则）、§4。本文件是术语表 + 产物 Schema 的展开抄录，供实现与断点续跑时快速查阅，不另立新规则。

## 一、术语表（规格 §1）

| 术语 | 含义 |
|---|---|
| 笔记包 | 一次运行的全部产物：图 + 文案 + 运行记录，落盘于 `06-产出/<run>/` |
| 分镜表 | 逐页规划表：每页的类型、职能、核心文字、视觉要点（`storyboard.md`） |
| 母版图 | 确认点 1 交付的封面图，后续内页风格以它为锚 |
| 回填协议 | 半自动生图的交接机制：工作流出提示词 → 人工生图放回指定路径 → 工作流校验后继续 |
| 探索模式 | 账号档案的初始状态：前 9-12 篇在 2-3 个候选领域轮换试题 |
| 账号档案 | 可换的账号配置：定位/人设/受众/候选风格/领域（`01-账号/账号档案.md`） |

## 二、产物 Schema（规格 §4）

### 2.1 运行目录（规格 §4.1）

```
06-产出/<YYYYMMDD-slug>/
├── run.yaml          # 见 2.2
├── research.md       # 对标摘要（或「未对标」声明）
├── storyboard.md     # 角度陈述 + 分镜表
├── prompts/          # cover-prompt.md、page-NN-prompt.md（仅 ai-image 页）
├── html/             # page-NN.html（html-card 页的中间产物，可改后重渲染）
├── images/           # cover.png、page-01.png …（纯英文命名，序号两位）
├── copy.md           # 标题候选×3（标注推荐）/正文/标签/评论区首条引导
└── receipt.md        # 发布回执（仅发布后存在）
```

人话解释：
- `<YYYYMMDD-slug>` 是一次运行的唯一目录名，`slug` 为英文短横线小写（如 `sleep-tips`）。
- `prompts/`、`html/` 是中间产物，允许人工检视或改后重渲染；`images/` 是最终成品图。
- `receipt.md` 只在真正发布成功后才会出现，是否存在本身就是「是否已发布」的信号。

### 2.2 run.yaml（规格 §4.2）

```yaml
run: 20260705-sleep-tips
topic: "用户输入的原始主题或提示词"
profile_version: "账号档案.md 顶部的 version 字段"
mode: 探索 | 深耕
domain: "本篇候选领域（探索模式必填）"
nodes:            # 九节点逐项
  - id: research
    status: ok | degraded | failed | in_progress | waiting_backfill | waiting_confirm
    tool: "xiaohongshu-mcp.search_feeds"
    retries: 0
confirmations:
  - point: 1
    result: approved | revised
    rounds: 1
  - point: 2
    result: published | approved_unpublished
degradations: []   # 降级说明列表
```

字段人话解释：
- `run`：运行目录名，同时也是本次运行的唯一 ID。
- `topic`：用户原始输入，未经加工，供回溯核对角度是否跑偏。
- `profile_version`：记录生成本笔记包时账号档案的版本号，防止档案后续变更导致的追溯歧义。
- `mode` / `domain`：探索模式下必须记录本篇实际所属候选领域，用于未来手动收敛判断。
- `nodes`：九个节点各一条记录，`status` 是断点续跑的唯一依据（见下方状态枚举）。
- `tool`：该节点实际调用的工具名（MCP 工具或脚本名），便于排查失败原因。
- `retries`：该节点已重试次数，超过节点规格里的轮次上限即应停止自动重试转问用户。
- `confirmations`：两个确认点（★1 视觉母版确认、★2 发布放行）各一条记录；`result` 记录用户的最终决定，`rounds` 记录经过几轮修改才通过。
- `degradations`：降级说明列表，每次触发降级路径（如节点②对标失败、节点⑤封面兜底走 HTML→PNG）都在此追加一条人可读说明。

**status 状态枚举（六态，完整）**：

| 状态 | 含义 |
|---|---|
| `ok` | 节点正常完成，产物可信 |
| `degraded` | 节点以降级路径完成（产物可用，但走了兜底逻辑，需在 `degradations` 里说明原因） |
| `failed` | 节点失败且未能通过重试/降级恢复，流程在此停止 |
| `in_progress` | 节点正在执行中；若在此状态被中断，产物视为不可信 |
| `waiting_backfill` | 节点暂停，等待用户完成回填协议（人工生图后放回指定路径） |
| `waiting_confirm` | 节点暂停，等待用户在确认点做出决定（★1 或 ★2） |

### 2.3 已发档案.jsonl（规格 §4.3，每行一条 JSON）

```json
{"date":"2026-07-05","title":"","note_url":"","topic":"","domain":"",
 "cover_template":"","style":"","pages":7,"publish_slot":"20:30",
 "metrics":{"views":null,"likes":null,"collects":null,"comments":null,"checked_at":null}}
```

人话解释：
- 每次成功发布（节点⑨）追加一行，是全部已发笔记的唯一可查索引。
- `domain` / `style` / `cover_template` 供未来做探索模式收敛分析用。
- `metrics` 本版一律置 `null`（数据回流接口，二期再接入抓取并回填真实数据）。

### 2.4 分镜表（规格 §4.4，`storyboard.md` 内的表格）

| 列 | 约束 |
|---|---|
| 页码 | cover, 01..NN（内页 4-7 页） |
| 类型 | `cover` / `html-card`（注明用哪个版式模板）/ `ai-image` |
| 职能 | 钩子 / 痛点共鸣 / 干货点N / 金句 / 总结CTA——每页唯一 |
| 核心文字 | 该页面上出现的实际文字（内页文字进模板变量） |
| 视觉要点 | 一句话（锚点/配色/情绪） |

人话解释：一页对应分镜表一行；「职能每页唯一」意味着分镜规划节点（④）必须保证没有两页承担同一职责，否则视为规划不合格需重写。

## 三、断点续跑规则（规格 §3，完整抄录）

本工作流设计上就有多个暂停点（回填协议、双确认点），跨会话中断是常态而非异常：

- 每个节点开始时将 run.yaml 中该节点置 `status: in_progress`，完成后置 `ok / degraded`；等待人工时置 `waiting_backfill` 或 `waiting_confirm`。
- **恢复语义**：新会话（或同会话被打断后）接到「继续 <run>」类指令时，读该 run 的 run.yaml，从最后一个 `status: ok/degraded` 节点**之后**继续；`waiting_*` 节点从等待动作本身继续（重新输出回填话术或确认请求）。
- **已批准的确认点不重复确认**（confirmations 里已有 `approved` 记录即跳过）。
- `in_progress` 状态的节点视为产物不可信，整节点重跑（产物覆盖写）。
