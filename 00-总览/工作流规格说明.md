# 小红书成稿工作流 · 规格说明（v2）

> 2026-07-14 修订。目标形态：只读研究引擎 + 技能化视觉引擎 + 双闸门复核 + 人工发布包。
> 本文件是当前实现与后续验收的权威规格。

## 0. 目标与非目标

**目标：** 输入一个主题（或一段提示词），工作流产出一篇符合平台约束的小红书图文笔记，经 Topic Gate 与 Visual Gate 两道闸门后生成人工发布包，用户手动发布，再由工作流补录归档。

**非目标：**

- 自动发布
- 自动评论 / 点赞 / 收藏 / 互动
- 视频笔记
- 批量流水线发布
- 绑定新的第三方付费生图通道

## 1. 总流程

```text
① 档案加载
② 只读研究
③ Topic Gate
④ 选题定角
⑤ 分镜规划
⑥ Style Router
⑦ 封面生产
★1 视觉母版确认
⑧ 内页生产
⑨ Visual Gate
⑩ 文案定稿
⑪ 组包终审
★2 发布包确认
⑫ Publish Pack（人工发布，手动补录）
```

补充约束：

- `04-工具/` 只放确定性脚本与工具边界说明。
- `05-验收/已发档案.jsonl` 是本地运行时文件；公开仓库只保留 `已发档案.example.jsonl` 模板。

## 3. 节点规格

| # | 节点 | 输入 | 输出 | 通过标准 | 失败处理 |
|---|---|---|---|---|---|
| ① | 档案加载 | 用户主题 / 提示词 | run.yaml 头部边界 | 档案存在，关键字段齐 | 停止并提示补档案 |
| ② | 只读研究 | 主题关键词 | `research.md` + `research-evidence.json` | 证据足够或合法降级 | 三后端都不可用则记 degraded |
| ③ | Topic Gate | 研究产物 + 最近 run 去重信息 | `topic-gate.md` + `topic-score.json` | verdict 合法且有证据 | `revise` 回 ②；`reject` 终止 |
| ④ | 选题定角 | research + 账号档案 | storyboard 头部角度陈述 | 三要素齐备 | 重写 1 次，仍不齐则问人 |
| ⑤ | 分镜规划 | 角度陈述 + 文案规范 | `storyboard.md` 分镜表 | 封面 1 + 内页 4-7，职能唯一 | 重写，超 2 轮问人 |
| ⑥ | Style Router | 分镜表 + 用户偏好 + style registry | `prompts/style-decision.md` | 路由结果可解释 | 命中拒绝规则则回分镜 / 改题 |
| ⑦ | 封面生产 | 分镜 + 风格路由 | `images/cover.png` | 3:4 通过 | 按 fallback 链降级 |
| ★1 | 视觉母版确认 | 封面 + 分镜 + 风格说明 | 用户确认记录 | 用户明确通过 | 回 ⑤ 或 ⑦ |
| ⑧ | 内页生产 | 分镜 + style decision + skill 知识 | `images/page-NN.png` | 每页成图合法 | 按页降级 |
| ⑨ | Visual Gate | 全套图片 + html 中间产物 | `visual-gate.md` + `visual-review.json` | 逐页 verdict 完整 | `revise` 重做；`fallback` 降级 |
| ⑩ | 文案定稿 | 分镜 + research + 文案规范 | `copy.md` | verify 所需字段齐全 | 自动压缩重写 |
| ⑪ | 组包终审 | 全部产物 | verify 报告 + 完整预览 | `verify.mjs` 退出码 0 | 回对应节点修复 |
| ★2 | 发布包确认 | 全套图 + copy + manual publish 预览 | 用户确认记录 | 用户确认标题与图片顺序 | 包保留，待后续继续 |
| ⑫ | Publish Pack | 确认后的笔记包 | `manual-publish.md`；发布后 `receipt.md` | 手动发布包完整 | 未回链则保持 package_ready |

## 4. 断点续跑

- 节点开始时置 `in_progress`，完成后置 `ok / degraded`。
- 等待人工回填时置 `waiting_backfill`；等待确认时置 `waiting_confirm`。
- 接到「继续 <run>」时，从最后一个 `ok / degraded` 节点之后继续。
- `workflow_mode` 缺省视作旧版 run。

## 7. 验收

升级完成的最低证明包括：

1. 一个测试 run 能产出 `research-evidence.json`、`topic-score.json`、`visual-review.json`、`manual-publish.md`
2. `run.yaml` 含 v2 新字段
3. `node 04-工具/verify.mjs <run>` 退出码为 0
4. 全程零调用 `publish_content` 与互动类工具
5. 仓库具备公开前所需的 README、LICENSE、模板文件、忽略规则与第三方依赖说明
