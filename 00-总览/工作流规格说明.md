# 小红书成稿工作流 · 规格说明（v1）

> 2026-07-02 定稿。上游依据：[`小红书成稿工作流定调结论.md`](../小红书成稿工作流定调结论.md)（已批准）。
> 本文件是实现计划（writing-plans）的唯一输入：实现时以本文为准，与定调结论冲突处以本文为准。

## 0. 目标与非目标

**目标**：输入一个主题（或一段提示词），工作流产出一篇符合小红书平台约束与算法判据的图文笔记（封面 1 张 + 内页 4-7 张 + 文案），经两次人工确认后通过 xiaohongshu-mcp 发布，并归档。

**非目标（明确不做，二期再议）**：

- 数据回流选题（仅在归档格式中预留 `metrics` 字段）
- 自动评论/点赞/回复等任何自动互动
- 视频笔记
- 批量/定时循环生产（单次运行只产出一篇）
- 全自动 AI 生图（本版为半自动回填，见 §5）

## 1. 术语

| 术语 | 含义 |
|---|---|
| 笔记包 | 一次运行的全部产物：图 + 文案 + 运行记录，落盘于 `06-产出/<run>/` |
| 分镜表 | 逐页规划表：每页的类型、职能、核心文字、视觉要点（`storyboard.md`） |
| 母版图 | 确认点 1 交付的封面图，后续内页风格以它为锚 |
| 回填协议 | 半自动生图的交接机制：工作流出提示词 → 人工生图放回指定路径 → 工作流校验后继续 |
| 探索模式 | 账号档案的初始状态：前 9-12 篇在 2-3 个候选领域轮换试题 |
| 账号档案 | 可换的账号配置：定位/人设/受众/候选风格/领域（`01-账号/账号档案.md`） |

设计纪律：

- 每个规范文件必须是**可执行判据**（能回答「过/不过」），不写理念散文。
- 外部项目（ponyo / visual-director / guizang）只裁剪内化进 `02-规范/`，注明出处；不整包引入、不产生运行时依赖。
- 图片相关路径一律纯英文（xiaohongshu-mcp 硬要求）；`<slug>` 为英文短横线小写（如 `sleep-tips`）。

## 3. 主流程（节点规格）

每个节点定义：输入 → 输出 → 通过标准 → 失败处理。执行者均为 Agent（读对应 prompt 文件），除非注明脚本。

| # | 节点 | 输入 | 输出 | 通过标准 | 失败处理 |
|---|---|---|---|---|---|
| ① | 档案加载 | 用户主题/提示词 | 本次创作边界（内存态，写入 run.yaml 头部） | 账号档案存在且含必填字段 | 档案缺失 → 停止，提示先建档案 |
| ② | 对标研究 | 主题关键词 | `research.md`：爆款标题结构、封面套路、评论区高频需求各 ≥3 条 | MCP 搜索返回 ≥5 条笔记 | 降级跳过，`research.md` 写「未对标」+ 原因，run.yaml 记 degradation |
| ③ | 选题定角 | research.md + 账号档案 | 角度陈述（写入 storyboard.md 头部）：1 个明确角度 + 核心利益点 + 目标情绪 | 三要素齐备且互相一致 | 重写 1 次，仍不齐 → 问用户 |
| ④ | 分镜规划 | 角度陈述 + 文案规范 | `storyboard.md` 分镜表 | 封面 1 页 + 内页 4-7 页；每页职能唯一且能答「为什么存在」；类型标记合法 | 重写，超 2 轮问用户 |
| ⑤ | 封面生产 | 分镜表 + 封面锚点判据 + 视觉风格库 + 账号档案候选风格 | `prompts/cover-prompt.md` → （回填协议）→ `images/cover.png` | 提示词含模板选型理由 + 锚点描述 + 尺寸 + 负面清单；回填图过尺寸校验（3:4 ±2%） | 校验不过 → 重新提示用户回填；回填 2 轮仍不过（或用户要求）→ **封面降级走 HTML→PNG 路线**：复用 card-statement 版式按大字报型封面填变量，经 render.mjs 出图（AI 生图渲染中文不可靠时的兜底，大字报型封面本就适合 HTML 制作） |
| ★1 | 视觉母版确认 | cover.png + storyboard.md + 风格说明 | 用户批准记录（run.yaml） | 用户明确说过 | 不过 → 依用户意见回 ④ 或 ⑤；最多 2 轮，仍不过暂停待人工指示 |
| ⑥ | 内页生产 | 分镜表 + 内页版式库 + 母版图风格锚 | `html/page-NN.html` → render.mjs → `images/page-NN.png`；ai-image 页走回填协议 | 每页渲染成功、1080×1440；文字无溢出（脚本检测 overflow） | 渲染失败重试，超 2 轮问用户 |
| ⑦ | 文案定稿 | 分镜表 + 文案规范 + research.md | `copy.md`：**标题候选 3 个（标注推荐项）**/正文/标签/评论区首条引导 | 每个标题候选 ≤20 字、正文 ≤1000 字（程序化字数校验）、标签 3-6 个、含评论引导 | 超限自动压缩重写，超 2 轮问用户 |
| ⑧ | 组包终审 | 全部产物 | 终审报告（追加进 run.yaml）+ 完整预览呈现 | 发布前检查清单全部硬校验项通过 | 未过项回对应节点修复 |
| ★2 | 发布放行 | 完整笔记包预览 | 用户放行记录 + **选定标题**（从 3 候选中挑）+ 可选定时（默认建议 20-22 点档） | 用户明确说「发」并选定标题 | 用户不发 → 包保留，流程正常结束（状态 `approved_unpublished`） |
| ⑨ | 发布与归档 | 笔记包 + 放行记录 + 选定标题 | MCP 发布回执 → `receipt.md` + 追加 `已发档案.jsonl` | publish 返回笔记 URL | **重试前先经 MCP 查询本账号主页最新笔记，确认首次未实际发出**（防回执超时导致重复发布——重发同图文是明确风控信号）；确认未发出才原地重试 1 次；已发出则视为成功、补记回执；再失败报错停止，产物保留，**绝不静默丢稿** |

流程约束：

- 产物**先落盘再进下一节点**；任何失败不损失已有产物。
- 节点 ⑤⑥ 生成图片前必须先确认 `06-产出/<run>/images/` 存在。
- 探索模式下，节点 ③ 须在角度陈述中标注本篇所属候选领域（写入归档 `domain` 字段）。

### 断点续跑规则

本工作流设计上就有多个暂停点（回填协议、双确认点），跨会话中断是常态而非异常：

- 每个节点开始时将 run.yaml 中该节点置 `status: in_progress`，完成后置 `ok / degraded`；等待人工时置 `waiting_backfill` 或 `waiting_confirm`。
- **恢复语义**：新会话（或同会话被打断后）接到「继续 <run>」类指令时，读该 run 的 run.yaml，从最后一个 `status: ok/degraded` 节点**之后**继续；`waiting_*` 节点从等待动作本身继续（重新输出回填话术或确认请求）。
- **已批准的确认点不重复确认**（confirmations 里已有 `approved` 记录即跳过）。
- `in_progress` 状态的节点视为产物不可信，整节点重跑（产物覆盖写）。

## 5. 半自动生图回填协议

1. 节点 ⑤（或 ⑥ 的 ai-image 页）产出提示词文件，内含：完整正向提示词（含锚点与风格描述，取自 02-规范）、尺寸 1080×1440（3:4）、负面清单（引用视觉风格库黑名单）、目标保存路径。
2. 工作流**暂停**，向用户输出固定话术：提示词位置 + 「请用任意生图工具生成后，保存为 `images/cover.png`，回复『图好了』」。
3. 用户回复后，程序化校验：文件存在、可读取、宽高比 3:4（允差 ±2%）。不过 → 说明原因，回到第 2 步。
4. 校验通过 → 继续流程。run.yaml 中该节点 `tool` 记 `"manual-image-backfill"`。

升级路径：未来接入生图 MCP 时，仅替换本协议第 2-3 步为工具调用，提示词文件格式不变。

## 6. 规范文件内容要求

实现时每个文件必须达到以下内容密度（这是实现计划的验收线）：

### 6.1 平台硬约束.md

标题 ≤20 字；正文 ≤1000 字；图 2-9 张、3:4（1080×1440）；本地纯英文路径；同账号单网页端登录；发布频率 ≤2 篇/天、间隔 ≥4 小时。每条注明校验方式（程序化字数/尺寸校验 or 人工）。

### 6.2 封面锚点判据.md（内化 ponyo，注明出处）

- 双变量模型一段话定义（信息密度 × 视觉锚点）。
- 6 模板：大字报型 / 人物情绪型 / 数字冲击型 / 对比型 / 清单型 / 场景实拍型——各含适用内容类型与提示词要点。
- 模板选型规则：内容类型 → 模板的映射表。
- **5 项过/不过诊断**（确认点 1 的验收表）：① 缩略图尺寸下利益点可读；② 有且仅有一个视觉锚点；③ 封面文字与标题互补不重复；④ 对比度足够；⑤ 信息密度适中（3 秒内可解析）。

### 6.3 视觉风格库.md（内化 visual-director，注明出处）

8 种风格：极简大字报 / 纪实生活感 / 手绘涂鸦标注 / 杂志编辑风 / 商务信息图 / 温暖插画 / 胶片拼贴 / 克制科技感。每种含：适用内容类型、提示词骨架、配色字体要点。附黑名单：蓝紫渐变、液态玻璃、塑料 3D 人物、油腻光效（提示词负面清单直接引用）。

### 6.4 内页版式库.md + templates/

5 个 HTML 模板（单文件、内嵌 CSS、`{{变量}}` 占位、1080×1440 画布）：观点大字卡 / 清单步骤卡 / 对比表卡 / 金句引用卡 / 总结CTA卡。索引文件记录每个模板的变量表与适用职能。模板须在 devicePixelRatio=2 下渲染不糊字。card-statement（观点大字卡）兼任封面降级路线的大字报型封面模板（见 §3 节点 ⑤ 失败处理），其变量设计须同时满足两种用途。

### 6.5 文案规范.md

标题公式库（数字型/悬念型/身份共鸣型/反常识型，各含例句）；**标题产出规则：每篇 3 个候选、覆盖不同公式、标注推荐项，确认点 2 由用户选定**；正文三段结构（首行钩子 → 价值展开 → 提问结尾）；标签策略（3-6 个：1 大流量 + 2 垂直 + 1 长尾）；评论区首条引导模板 ≥3 条。

**评论区首条引导语的执行者是用户本人**：发布后由用户手动贴到笔记评论区（发布后 1 小时内，配合算法加权）。工作流及 Agent 在任何情况下**不得调用评论类 MCP 工具**代发（自动互动是本项目自定的风控红线）；receipt.md 中附引导语文本并提醒用户手动发布。

### 6.6 风控清单.md

禁词分类：引流类（微信/V./公众号/私信我 等）、绝对化用语、医疗金融断言；敏感话题清单；程序化扫描方式（字符串匹配即可，词表就在本文件内维护）。

## 7. 账号档案.md（初始内容）

```yaml
version: 1
mode: 探索           # 探索 | 深耕
persona: 待定        # 人设一句话
audience: 待定       # 目标受众
candidate_domains: [] # 2-3 个候选领域，首跑前必填
candidate_styles: []  # 从视觉风格库标注 2-3 种
tone: 待定           # 语气关键词
```

规则：`mode: 探索` 时按 `candidate_domains` 数组顺序循环轮换（第 N 篇取第 `N mod 领域数` 项；用户指定主题明显属于某领域时以主题为准并记录实际 domain）；累计 9-12 篇后依已发档案手动收敛为 `mode: 深耕`（本版不自动收敛）。**首跑前置条件**：`candidate_domains` 与 `candidate_styles` 非空——由用户在首次运行的对话中与 Agent 一起填写。

## 8. 工具层

### 8.1 MCP 工具映射（xiaohongshu-mcp @ http://localhost:18060/mcp）

| 工作流节点 | MCP 工具 | 降级 |
|---|---|---|
| 前置检查 | check_login_status | 未登录 → 停止，提示扫码 |
| ② 对标研究 | search_feeds → get_feed_detail | 失败 → 降级跳过 |
| ⑨ 发布 | publish_content（支持定时） | 失败 → 先查主页确认未发出，再重试 1 次 → 停止保留产物 |
| ⑨ 重试前防重检查 | 用户主页查询工具（实测时确认具体工具名） | 查询失败 → 视为「未发出状态不明」，**不自动重试**，停止问人 |

其余 MCP 工具（评论/点赞/收藏等）**本版不使用**（风控红线；评论区首条引导语由用户手动发布，见 §6.5）。

### 8.2 render.mjs（确定性脚本）

- 依赖：puppeteer（`小红书/package.json` 唯一依赖，实施第一步安装并验证）。
- 输入：`06-产出/<run>/html/*.html`；输出：同名 `images/*.png`。
- 参数：viewport 1080×1440、deviceScaleFactor 2、输出 2160×2880 PNG（2 倍图，比例仍为 3:4，平台接受且更清晰，免引入缩放依赖）。
- 自检：渲染后检测页面内容溢出（scrollHeight > viewport 即报错），溢出视为节点 ⑥ 失败。
