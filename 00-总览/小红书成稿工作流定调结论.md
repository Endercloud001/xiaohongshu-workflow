# 小红书成稿工作流定调结论（v2）

## 一句话

把原来的「九节点成稿 + MCP 自动发布」定调为「只读研究引擎 + 可插拔视觉引擎 + 双闸门复核 + 人工发布包」。

## 当前定调

1. 不再通过 MCP 自动发布。
2. xiaohongshu-mcp 只保留研究兜底用途。
3. 配图阶段走技能路由：封面、内页、结构化信息页分别按 registry 选择最合适的 skill。
4. 研究之后加 Topic Gate，成图之后加 Visual Gate。
5. 最终产物不是发布回执，而是 `manual-publish.md`；发布动作由用户手动完成，再补录 `receipt.md`。

## 为什么这样定

- 自动发布与自动互动的风控成本太高，不值得继续放在主链。
- 当前仓库已经具备脚本、run 目录、verify 机制和两套视觉知识资产，最合理的升级是削薄风险，而不是推倒重做。
- 研究、视觉、发布三个层面的职责现在更清晰：研究只读、视觉可插拔、发布人工兜底。

## 结果

这个仓库从「自动发帖流程」变成了一套更适合长期维护和公开发布的创作工作流。
