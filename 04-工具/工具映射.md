# 工具映射

> 工作流各节点用到的外部工具、本地脚本、生图通道与降级规则。

## 1. MCP 工具（xiaohongshu-mcp @ http://localhost:18060/mcp）

| 工作流节点 | MCP 工具 | 边界与降级 |
|---|---|---|
| 前置检查 | `check_login_status` / `get_login_qrcode` | 仅在 OpenCLI 不可用时才要求 xiaohongshu-mcp 登录态 |
| ② 只读研究 | `search_feeds` → `get_feed_detail` | OpenCLI 不可用时的研究兜底；失败 → research 记 degraded |

### 1.1 工具边界（写死）

| 工具 | 允许 | 禁止 |
|---|---|---|
| xiaohongshu-mcp | `check_login_status`、`search_feeds`、`get_feed_detail`（仅作研究兜底） | `publish_content` 及一切评论 / 点赞 / 收藏 / 互动工具 |
| agent-reach（OpenCLI） | `opencli xiaohongshu search/note`（研究首选） | 一切写操作 |
| redbook（可选） | `whoami / search / read / comments / topics / feed / user / user-posts / analyze-viral / viral-template / health / boards / board` | `post / comment / reply / batch-reply / collect / uncollect` |
| image-gen-mcp | `generate_image` | — |

## 1.5 研究后端与可选增强

运行时语义是 `OpenCLI（agent-reach）` 首选、`redbook` 可选增强、`xiaohongshu-mcp` 在 OpenCLI 不可用时兜底；不把三者改为依次互斥的后端选择链。

- OpenCLI 可用：直接作为研究主路径，run.yaml `research_backend: opencli`
- redbook 已安装且 `redbook health` 入口检查通过：可选用于扩充证据面；若本次研究实际仅命中 redbook，run.yaml 记 `research_backend: redbook`
  - redbook 认证必须按其官方文档在仓库外完成；公开仓库不记录真实账号名、登录状态、Cookie 内容、认证命令实参或本机凭据路径。
- OpenCLI 不可用，但 xiaohongshu-mcp 已登录：走 `search_feeds/get_feed_detail`，run.yaml `research_backend: xiaohongshu-mcp`
- 未命中任何研究后端：run.yaml `research_backend: none`，research 记 `degraded`，`research.md` 写「未对标」和原因

## 2. 本地脚本（零 / 单依赖，确定性）

| 脚本 | 用途 | 用法 | 退出码 |
|---|---|---|---|
| `04-工具/render.mjs` | HTML → PNG 渲染（1080×1440 → 2160×2880），溢出检测 | `node 04-工具/render.mjs <运行目录>` | 0=全成功 / 1=有溢出 FAIL / 2=用法或环境错误 |
| `04-工具/verify.mjs` | 发布前硬校验（标题 / 正文 / 标签 / 图片 / 风控词） | `node 04-工具/verify.mjs <运行目录> [词表md路径]` | 0=全过 / 1=校验不过 / 2=用法或文件缺失 |
| `04-工具/normalize-cover.mjs` | AI 封面原图 → 精确 1080×1440（2160×2880@2x）3:4 | `node 04-工具/normalize-cover.mjs <运行目录>` | 0=成功 / 1=源图不可解码 / 2=用法或环境错误 |
| `04-工具/normalize-image.mjs` | 任意源图 → 精确 1080×1440（2160×2880@2x）3:4 | `node 04-工具/normalize-image.mjs <运行目录> <源相对路径> <出相对路径>` | 0=成功 / 1=源图不可解码 / 2=用法或环境错误 |
| `.claude/skills/guizang-social-card-skill/validate-social-deck.mjs` | html_png 页面版式校验（R1-R9） | `node .claude/skills/guizang-social-card-skill/validate-social-deck.mjs <html目录或index.html> [--style=]` | 0=通过 / 1=内容不合格 / 2=用法或环境错误 |

依赖：`render.mjs` / `normalize-*` 需 puppeteer；guizang validator 仅在用户已于本地显式安装并启用该外置 skill 时可用，并依赖该 skill 目录内的 Playwright 安装。

### 2.1 安装与许可证边界

- Puppeteer 通过 npm 安装，`node_modules/` 与其下载的浏览器可执行文件不得提交。
- OpenCLI、redbook 与 xiaohongshu-mcp 均为仓库外工具；Cookie、认证状态和浏览器 profile 不得进入仓库。
- `cover-anchor-system` 上游未声明许可证，具有无许可证的使用与再分发风险；不随仓库分发，只有用户在仓库外显式安装后才可能按 `style-registry.yaml` 参与路由。
- `guizang-social-card-skill` 上游许可证为 AGPL-3.0，使用者须评估并履行 AGPL 义务；不随仓库分发，只有用户在仓库外显式安装后才可能按 `style-registry.yaml` 参与路由。
- 完整来源、许可证与字体 / 图片 / 模板审计见 [`../THIRD_PARTY_LICENSES/README.md`](../THIRD_PARTY_LICENSES/README.md)。

## 3. 生图通道（产线乙 · image-gen-mcp）

封面与内页均复用 `mcp__image-gen-mcp__generate_image`（模型 `gpt-image-2-official`，经 apimart 中转）。

- 封面：`prompts/cover-prompt.md` → `generate_image(size=auto, quality=high)` → `assets/cover-src.png` → `normalize-cover.mjs` → `images/cover.png`
- 内页：`prompts/page-NN-prompt.md` → `generate_image(size=1024x1536, quality=medium)` → `assets/page-NN-src.png` → `normalize-image.mjs` → `images/page-NN.png`

## 3.1 降级链

- 封面：`cover-anchor-system` → `guizang-social-card-skill` → `html-templates`（前两项仅在本地显式安装并启用时参与路由）
- 内页：`xhs-visual-director` → `guizang-social-card-skill` → `html-templates`（guizang 仅在本地显式安装并启用时参与路由）
- 任一环节失败（生图失败 / skill 缺失 / normalize FAIL / Visual Gate 不过）都按 fallback 链逐级降级
